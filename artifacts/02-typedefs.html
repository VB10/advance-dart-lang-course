Sipariş formu: fonksiyon typedef'i

dart.dev · typedefs

Sipariş formu: ürün adı, adet ve fiyat alanları aynı imzalı doğrulayıcılarla kontrol ediliyor.

Girdiad: '', adet: 0, fiyat: 12.5

Olumsuz String? Function(int?) her parametrede
⚠
Üç doğrulayıcı, üç ayrı imza
String? Function(String?) · String? Function(int?) · String? Function(double?)

Aynı sonuç, imza her yerde elle yazılıyor.

Olumlu Validator quantityRule
✔
Hatalar: Ürün adı boş, Adet en az 1

Aynı sonuç, imza bir kez adlandırıldı.

Neden: Typedef imzaya isim verir, yeni tip yaratmaz. Eski sözdizimi (typedef T Name(S s)) yasak; typedef Validator<T> = String? Function(T? value); yaz. Tek yerde geçen fonksiyon tipini inline bırak.

Havale: isimli parametre

dart.dev · typedefs

Olumsuz String Function(String, String, int)
⚠
veli → ali: 5000 kuruş
Para ters yöne gitti

Fatura toplamı: Json alias

dart.dev · typedefs

Fatura ekranı: API'den gelen satırların fiyatları toplanıyor. İlk satırın fiyatı tam sayı geldi.

Girdi[{name: Kalem, price: 4}, {name: Defter, price: 12.5}]

Olumsuz row['price']! as double
⚠
Fatura açılamadı
TypeError: type int is not a subtype of double

JSON'daki 4, int geldi; as double patladı.

Olumlu typedef Json = Map<String, Object?>; + as num
🧾
Toplam 16.5

4 + 12.5, ikisi de kabul edildi.

Neden: Json alias'ı Map<String, Object?> ile birebir aynıdır; dynamic değil Object? kullan. JSON sayısı int de gelebilir: (x as num).toDouble(). Domain'e Json sızdırma, entity döndür.

Sipariş no ile müşteri no: alias yeni tip değildir

dart.dev · extension types

Fatura başlığı: sipariş numarası 7, müşteri numarası 1042. İki numara aynı türde.

Girdisipariş 7, müşteri 1042

Olumsuz typedef OrderIdAlias = int; typedef CustomerIdAlias = int;
⚠
Sipariş #1042, müşteri #7
Sıra ters verildi, yine de derlendi

İki ID de int; yer değişince de derlenir.

Olumlu extension type const OrderId(int value)
🧾
Sipariş #7, müşteri #1042

Ayrı tipler; ters sırayı analyzer reddeder.

Neden: typedef X = int yalnızca isimdir, int kabul eden her yer onu kabul eder. Karışmaması gereken ID ve birimler için extension type (Dart 3.3) sıfır maliyetli ayrı tip verir.

Stok ve fiyat: AsyncResult

dart.dev · typedefs

Ürün sayfası: stok ve fiyat sorgulayan servis, hata fırlatmayıp sonuç dönüyor.

Girdisku: kalem

Olumsuz Future<Result<int>> her metotta
📦
Stok: 12
Future<Result<int>> · Future<Result<double>> elle yazıldı

Aynı sonuç, imza her metotta yeniden yazıldı.

Olumlu typedef AsyncResult<T> = Future<Result<T>>;
📦
Stok: 12
AsyncResult<int> · AsyncResult<double>

Aynı sonuç, imza tek yerden değişir.

Neden: Alias yeni tip değildir: AsyncResult<int> == Future<Result<int>>. Kazanç okunabilirlik ve imzayı tek yerden değiştirebilmek. Tek metotluk serviste inline yaz. İki ekran da aynı çıktıyı verir; fark koddadır.

4

Mağaza konumu: record alias

dart.dev · records

Mağaza seçme ekranı: seçilen mağazanın konumu haritaya gidiyor. Boylam yanlışlıkla başa yazıldı.

Girdilat 41.0, lng 29.0

Olumsuz (double, double) storeWrong() => (29.0, 41.0)
📍
Enlem 29.0
.$1 enlem diye boylamı okudu

Konumsal record'da sıra hatası derlenir.

Olumlu typedef Point = ({double lat, double lng});
📍
Enlem 41.0, boylam 29.0

İsim anlamı belirler, sıra değil.

Neden: Alan isimli record alias'ı p.lat okutur; typedef OnPicked = void Function(Point point); callback şeklini de adlandırır. Tek yerde geçen küçük record için alias yazma. Ne zaman hangisi: birkaç değer tek parça dolaşıyorsa ya da fonksiyondan birden fazla değer dönüyorsa isimli record; davranış ya da 3'ten fazla alan varsa class (kart 7); tek değer ve karışmaması gerekiyorsa extension type (kart 3); çağrıda okunurluk için named parametre (kart 5).

Düzelt
/dartadvance Projemde konum, boyut ya da aralık için `(double, double)` gibi konumsal record kullanan yerleri bul, isimli alanlı `typedef` ile düzelt, test yaz.
Üret
/dartadvance Bana mağaza seçme ekranı için konumu ve seçim callback'ini typedef ile adlandıran bir harita sınıfı yaz.
